# Read-only native WFP snapshot prototype

`WfpPolicy.NativeReadback` is a read-only BFE/WFP snapshot reader. `WfpPolicy.Runtime` references it and contains a value adapter, but no concrete `IWfpPolicyStore`, `CapturePipe`, or readiness/activation gate invokes that adapter. Its CsWin32 allowlist contains engine-open/read-transaction/enumeration/free-memory APIs only; it contains no WFP add/delete binding.

The snapshot decoder copies bounded provider, sublayer, callout, provider-context, filter, condition, supported tagged scalar fields, and bounded `FWP_BYTE_BLOB_TYPE` conditions into managed records. Returned collections and byte data are copied into read-only views. Enumeration is paged and capped. BFE result arrays and enumeration handles are released in `finally` paths, and a failed read aborts its read-only transaction before closing the engine handle.

This prototype always reports an incomplete snapshot. Within the read transaction it requests owner, group, and DACL security information for each provider, sublayer, layer, callout, provider context, and filter; it bounds and parses the self-relative descriptor, rejects noncanonical DACLs, retains normalized owner/group/DACL SDDL plus its SHA-256 and descriptor metadata, and frees the WFP allocation on success and failure paths. It does not request SACL data: BFE ignores SACL ACEs and uses its own auditing. Every normalized descriptor still carries a policy-unverified issue because it has not been compared with an approved service ACL. A global issue also records that the service cannot prove enumeration coverage for objects hidden by per-object read ACLs. Callouts are enumerated and each filter callout reference is checked for presence and layer consistency. Layers are enumerated in the same transaction; their security descriptors are read with `FwpmLayerGetSecurityInfoByKey0`, each filter layer is resolved, and a null filter sublayer key is mapped through `FWPM_LAYER0.defaultSubLayerKey` before verifying the effective sublayer. Non-null optional provider keys on filters, sublayers, callouts, and provider contexts are checked against returned providers; null pointers remain valid. Missing rows remain unresolved because per-object READ ACLs may hide them. Provider contexts are enumerated in the same explicit read transaction; filter context references are checked against returned context keys, and empty or duplicate context keys fail closed. Empty keys do not trigger a descriptor query that could select the container descriptor. The reader accepts provider contexts with callout terminating, inspection, or unknown actions when `FWPM_FILTER_FLAG_HAS_PROVIDER_CONTEXT` applies; the official Microsoft classify-options sample uses an inspection action. Payload decoding supports `FWPM_GENERAL_CONTEXT` byte blobs and bounded (`64` entries) `FWPM_CLASSIFY_OPTIONS_CONTEXT` values: unicast and multicast/broadcast lifetimes plus multicast-state and loose-source-mapping values with `FWP_UINT32` tags and documented enum allowlists (0–2 and 0–1). Null, oversized, duplicate, unknown, unsupported, or out-of-enum classify options fail closed. IPsec and other provider-context union payloads remain explicitly incomplete until their full nested policy structures are normalized. The Microsoft API documents that a null template requests all contexts, enumeration only returns objects the caller can read, and returned entry arrays (not individual entries) are freed with `FwpmFreeMemory0`; the reader follows those ownership rules. A filter's returned `effectiveWeight` is accepted as normalized scalar evidence only when it is a valid `FWP_UINT64`; the BFE documentation defines the effective filter weight as `FWP_UINT64` and distinguishes it from the input `weight` tag used for automatic or range-based assignment. The reader does not infer global arbitration across sublayers from that scalar. Unsupported native condition values are explicit incomplete issues. `WfpPolicy.Runtime` contains a value adapter that rejects every incomplete snapshot and only maps the exact persistent AppID block shape the baseline coordinator understands. It retains the immutable native snapshot and a canonical projection of the mapped provider, sublayer, and filters. The adapter is not used by a concrete store, readiness gate, or `CaptureService`; the current reader's incomplete status prevents it from reaching a mutation path. The fixture harness therefore proves parsing and cleanup only against unmanaged test descriptors; it does not prove a live BFE read, ACL coverage, policy equivalence, or enforcement. See Microsoft's [FWPM_PROVIDER_CONTEXT0](https://learn.microsoft.com/en-us/windows/win32/api/fwpmtypes/ns-fwpmtypes-fwpm_provider_context0), [FWPM_PROVIDER_CONTEXT_TYPE](https://learn.microsoft.com/en-us/windows/win32/api/fwpmtypes/ne-fwpmtypes-fwpm_provider_context_type), [provider-context enumeration](https://learn.microsoft.com/en-us/windows/win32/api/fwpmu/nf-fwpmu-fwpmprovidercontextcreateenumhandle0), [provider-context page ownership](https://learn.microsoft.com/en-us/windows/win32/api/fwpmu/nf-fwpmu-fwpmprovidercontextenum0), [FwpmFreeMemory0](https://learn.microsoft.com/en-us/windows/win32/api/fwpmu/nf-fwpmu-fwpmfreememory0), [FWPM_CLASSIFY_OPTION0](https://learn.microsoft.com/en-us/windows/win32/api/fwpmtypes/ns-fwpmtypes-fwpm_classify_option0), [FWPM_CLASSIFY_OPTIONS0](https://learn.microsoft.com/en-us/windows/win32/api/fwpmtypes/ns-fwpmtypes-fwpm_classify_options0), [Using Classify Options](https://learn.microsoft.com/en-us/windows/win32/fwp/using-classify-options), [layer security descriptor and free rule](https://learn.microsoft.com/en-us/windows/win32/api/fwpmu/nf-fwpmu-fwpmlayergetsecurityinfobykey0), [WFP security descriptor API](https://learn.microsoft.com/en-us/windows/win32/api/fwpmu/nf-fwpmu-fwpmprovidergetsecurityinfobykey0), [provider-context security descriptor and free rule](https://learn.microsoft.com/en-us/windows/win32/api/fwpmu/nf-fwpmu-fwpmprovidercontextgetsecurityinfobykey0), [WFP access-control model](https://learn.microsoft.com/en-us/windows/win32/fwp/access-control), [FWPM_FILTER0](https://learn.microsoft.com/en-us/windows/win32/api/fwpmtypes/ns-fwpmtypes-fwpm_filter0), [FWPM_LAYER0](https://learn.microsoft.com/en-us/windows/win32/api/fwpmtypes/ns-fwpmtypes-fwpm_layer0), [layer enumeration](https://learn.microsoft.com/en-us/windows/win32/api/fwpmu/nf-fwpmu-fwpmlayercreateenumhandle0), and [Filter Weight Assignment](https://learn.microsoft.com/en-us/windows/win32/fwp/filter-weight-assignment) documentation.

The `LayerSnapshot` retains `layerKey`, `defaultSubLayerKey`, and a normalized layer security descriptor. The descriptor still requires comparison with an approved service ACL policy; the reader's global incompleteness and adapter rejection remain in place.

Build and run the unmanaged fixture harness on Windows with the pinned .NET SDK:

```powershell
dotnet restore tests/WfpPolicy.NativeReadback.Harness.csproj --locked-mode -p:NuGetAudit=false
dotnet build tests/WfpPolicy.NativeReadback.Harness.csproj -c Release --no-restore -p:Platform=x64
dotnet run --project tests/WfpPolicy.NativeReadback.Harness.csproj -c Release -p:Platform=x64 --no-build --no-restore
```

The fixture harness injects an in-memory native API fake and does not open BFE or call WFP, Sandbox, or host firewall APIs. The §251 follow-up adds offline checks for the `RPC_C_AUTHN_WINNT` engine-open argument and exact-cap/sentinel-page behavior. With the pinned .NET SDK 10.0.401, the locked restore completed, the x64 Release build succeeded with 0 warnings/errors, and all 34 fixture checks passed. The native page request remains capped at `WfpReadbackLimits.PageSize` (64): a full page that reaches `MaxObjects` causes one more bounded query, an empty sentinel completes enumeration, and any returned extra object is rejected before it is appended. The harness also covers layer/default-sublayer resolution, optional provider ownership references, callout/provider-context references, general and classify-options context payloads, malformed and over-limit option arrays, unsupported option kinds/value tags, malformed/noncanonical descriptors, descriptor-fetch errors that still return owned memory, and allocation cleanup on enumeration and enum-destroy failures.

`WindowsWfpApi.OpenEngine` now supplies `RPC_C_AUTHN_WINNT` (10), matching the existing read-only Sandbox capability observation; the injected harness assertion exercises that argument without calling `FwpmEngineOpen0`. This does not establish access for an administrator-installed service identity or constitute live BFE validation. The reader remains incomplete and read-only; it is not a production store and cannot mutate policy. Service installation and authorization, complete object visibility, approved ACL comparison, unsupported IPsec context decoding, production WFP apply/readback/rollback, per-lease worker/Chromium isolation, disposable Sandbox validation, and authorized successful capture evidence remain external gates.
