### 2026-10-11 caller-side network ownership audit

The default pipeline previously resolved `v.douyin.com` short links before checking the isolation broker. That could issue DNS/HTTPS from the ordinary CLI even though `open_system_broker()` later rejects capture. The pipeline now uses a network-free direct-URL resolver by default, and `--dry-run` uses the same resolver; short links return `BROWSER_ISOLATION_UNAVAILABLE` until a trusted worker exists. This closes the observed pre-broker network path for default product entry points.

A second dataflow gap remains before any service can be connected: `BrowserCapture` returns media candidates to `pipeline.py`, and the normal download executor performs DNS, CDN requests, redirects, and media-byte transfer in the caller process. The future IPC request must carry the original URL plus bounded resource limits; one per-lease worker must resolve short links, capture the page, validate candidates, follow media redirects, and download the media. The response may contain bounded safe metadata and a validated media stream/file, but no signed upstream URL, headers, candidate list, or socket capability. The current `open_system_broker()` remains unavailable and fail closed; no worker transport is implemented. The default caller-side short-link path and protocol codec now have local regression coverage; this does not establish a service or isolated network path (§135).

A protocol-only v1 codec/schema now defines that full-job message shape in `skills/douyin-transcript/src/douyin_transcript/capture_ipc.py` and `skills/douyin-transcript/references/capture-ipc-v1.schema.json`. It rejects duplicate/unknown fields, oversized frames, non-Douyin source hosts, and unsupported ports; result metadata contains an opaque artifact UUID and digest, never a filesystem path or signed URL. Result decoding also requires the originating request and enforces its request ID, media-size, and duration limits. Codec and caller-side routing regressions pass locally (§135). The actual authenticated IPC transport and bounded media-byte transfer remain unimplemented.

**Profile/login boundary (AUD-88):** `BrowserCapture` uses a persistent profile owned by the caller's user and retains it across runs. A future worker SID cannot safely reuse that profile without an explicit protected credential-sharing and locking design. Also, `LOGIN_REQUIRED` currently returns an error and closes the capture; it does not wait for the user to sign in and continue. Recommended V1 behavior is a separate temporary profile per lease, a visible browser with an explicit pause/resume handoff for authorized manual login, and profile cleanup when the lease ends. Do not copy cookies between identities. Persistent login across leases needs a separate design and acceptance.

#### Scope design review (2026-10-13; candidate only)
